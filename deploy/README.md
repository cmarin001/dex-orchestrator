# Deploy on a DigitalOcean droplet

Use Ubuntu 24.04 with at least 2 GB of RAM. Use SSH keys and allow port 22
from your administration network. Dashboard and MCP bind to loopback by
default. Open 80 and 443 only if deploying the HTTPS proxy. Keep 8787 and
8788 private when using a proxy or SSH tunnel.

## Install

Install Node under /usr/local so systemd can execute it without a shell
profile. The pinned baseline is Node 20 (20.19+). For that baseline, download
the matching [official Node 20 Linux archive](https://nodejs.org/en/download/archive/v20) for the droplet architecture,
verify it against the official signed checksums, then extract with
`sudo tar -xJf node-v20.*-linux-x64.tar.xz -C /usr/local --strip-components=1`.
Use the arm64 archive on an ARM droplet. Node 20 has reached end of life. Use a supported Node LTS for a
new internet-facing installation. Run `/usr/local/bin/node --version` to check it.

Create a non-root service account once:

```sh
sudo useradd --system --create-home --shell /usr/sbin/nologin dex
sudo install -d -o dex -g dex -m 0750 /opt/dex-orchestrator
```

Clone the repository into /opt/dex-orchestrator as the service account using
the deployment credentials for the repository. From the checkout run:

```sh
sudo -u dex install -m 0600 .env.example .env
sudo -u dex install -d -m 0700 data data/controls
sudo -u dex npm ci
sudo install -m 0644 deploy/systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
```

Populate .env with `OPENAI_API_KEY`, a watchlist or enabled discovery, and a
random `DASHBOARD_API_TOKEN` such as one generated by `openssl rand -hex 32`.
Keep .env at mode 600. Use JSON watchlists on a single line. All three services
use the same paths. Keep audit.jsonl, risk-config.jsonl and controls under
data on the droplet or a mounted local volume. Include all three in backups.
If moving the writable paths outside data, update the units and mount ordering.

```sh
sudo systemctl enable --now dex-worker dex-dashboard
sudo systemctl enable --now dex-mcp  # Optional remote MCP over HTTP
journalctl -u dex-worker -u dex-dashboard -u dex-mcp -f
```

For an update from /opt/dex-orchestrator:

```sh
sudo -u dex git pull --ff-only && sudo -u dex npm ci && sudo systemctl restart dex-worker dex-dashboard dex-mcp
```

Omit dex-mcp if you use stdio only. Restart the dashboard or MCP unit alone to
update its environment without interrupting worker execution.

## Optional HTTPS proxy

Point your DNS record at the droplet and use Caddy. The upstream services
enforce `Authorization: Bearer <DASHBOARD_API_TOKEN>`. Caddy forwards that
header and handles TLS. For MCP set
`MCP_ALLOWED_HOSTS=desk.example.com,127.0.0.1:8788` in .env.

```caddyfile
desk.example.com {
    handle /mcp {
        reverse_proxy 127.0.0.1:8788
    }
    handle {
        reverse_proxy 127.0.0.1:8787
    }
}
```

Check the authenticated `/api/v1/health` endpoint before connecting clients.
Set `DASHBOARD_ORIGIN` to the exact browser frontend origin for direct CORS.

## Live worker

Use a worker-only secret file and a dedicated live audit journal. See
[worker isolation and the live release checks](../docs/live-runbook.md)
before enabling the live worker on a droplet or in a container.
