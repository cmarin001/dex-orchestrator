# Frontend API contract review

Frontend reviewed at [84ccb72](https://github.com/cmarin001/dex-orchestrator-app/commit/84ccb725c56ad62ad9ef2a05966ca98e8e40a64c). This commit was originally exported as beam-arrow-hazel-delta; GitHub now resolves that repository to dex-orchestrator-app. Backend compared at [977f705](https://github.com/cmarin001/dex-orchestrator/commit/977f705f2fa9b7b5b179d5e21885b19b045875f1). This document requires approval before endpoint work.

**The deployed interface described by this commit is a local paper desk.** The desk has zero orchestrator HTTP call sites, polling hooks, receipt polling, or SSE subscribers. The endpoint strings in `src/desk/data.ts:324–345` are rendered as static coverage rows. `src/desk/store.ts:108–122` creates local IDs, receipts, and audit events. `src/desk/pages/system.tsx:130` says no worker is attached. This contract specifies the backend surface independently of client adoption. A later frontend change can replace the fixture reads and local control handlers with the documented requests.

The last column is the traceability matrix. An endpoint ID identifies the existing or proposed backend operation for the control. For authenticated existing routes the deployment selects legacy bearer or OAuth bearer via the BFF. Keep worker controls behind the configured authentication and existing elevation checks. Validation errors return 400, missing/invalid credentials 401, denied privilege or step-up 403, conflicts on actor/action/ID reuse 409, and journal or service failures can return 503. Existing queued command responses are 202 with `request_id`, `actor`, normalized `action` and `state: "queued"`. The worker applies queued actions next cycle. Resubmit the same actor, action and ID for the latest receipt. A terminal receipt may return 200, which is separate from initial acceptance. The desk expects none of these wire semantics yet. Its local `Receipt` is `{ id, at, action, status }` with `pending | success | danger`; most actions immediately create a success row.

### Submission, reads and errors

- All proposed endpoints use the existing operator authentication path. Use 400 for invalid bodies or ranges, 401 for missing credentials, 403 for role or elevation failures, 404 for inaccessible or unknown IDs, 409 for stale revision, ID conflict, expired or consumed quote, and 503 for unavailable data or durable storage. Use the same JSON error envelope across the new endpoints.
- For a combined risk form, validate both risk configuration and trading caps before committing changes. An individual risk change uses RISK_WRITE; a limits-only change uses LIMITS_WRITE. If one operator action edits both, extend RISK_WRITE with optional limits and both revisions and apply the pair atomically under one receipt. Do not have the frontend issue two writes for that case.
- The kill switch records a durable entry and live-send block on intake independently of the health endpoint. Resume or arm requires a separate authorized action with the emergency gate explicitly cleared through breaker reset; clearing the gate never resumes entries or arms live by itself. Finish reconciliation of in-flight transactions before a restart can resume normal operations. A flatten request queues paper position closes through the worker and reports per-position outcomes in audit. If the worker is down, the action remains queued and does not claim that positions closed.
- Quote preview returns explicit unsupported chain or route errors. Manual order intake is paper-only in this contract, and its worker path retains the existing approvals, risk, rug, position and amount checks. Reconcile is observation only.
- Existing authenticated reads can feed overview and live monitoring without requiring a new stream. Live prices may reuse GET /live-view/stream if adopted later. Export buttons continue to serialize data returned by the mapped read endpoints.

### Shape and safety gaps

- **Position and trade identity** — The desk fixture `Position` and `ClosedTrade` in `src/desk/data.ts` use camelCase, stub IDs, numeric marks and fixture market statistics. The backend exposes run IDs, canonical chain/address fields, seconds, USD fields and nullable marks. Open-position market depth, FDV, holders, volume and change windows require real measurements. Do not substitute zero or convert a fixture symbol into a real order.
- **Audit** — `AuditEvent` expects synthetic agent names, severity and a flat detail map. Backend journal events provide stage, status, identity and arbitrary details. Preserve the original record for support. Pagination and search across unloaded pages are absent from the desk. JSONL and other exports serialize local data only.
- **Risk, budget and chains** — The current RiskConfig defines fractional risk/depth/drawdown, integer basis points and an exit ladder. The desk displays whole percentages and dollar trading caps. The Phase 3 BudgetConfig controls provider spend, so the proposed LIMITS_WRITE and combined RISK_WRITE contract give the daily/per-trade trading fields their own worker-enforced limits. ChainRouting uses fractional allocations, canonical chain keys, asset classes and enabled-chain filters. The UI fixture IDs include `arbitrum` and `bsc`; enablement requires verified, configured support.
- **Emergency control** — Pause-only in the kill dialog also changes the local live flag. Two separate normal control requests would not establish a single durable emergency action. Approve an explicit safety design first. Intake must not call other health/status endpoints. A stopped worker cannot apply a queued command or close positions until it can run. Separate acknowledgement, disarm enforcement, and any position-close results.
- **Manual trading** — The preview is local math with hard-coded liquidity; submission uses a symbol-like free-text token and may close a matching simulated position or create a simulated position even on an unmatched sell. A connected implementation requires verified identities, typed quote and amount units, route applicability, authorization and paper-scope enforcement. The current handler supplies none of the guards needed to authorize a live order.
- **Unwired UI** — No candidates screen, position price stream, receipt refresh, server-backed live audit, connection form, provider-budget input, or memecoin-filter editor is reachable. The store contains `setProviderBudget` without a UI caller. The System coverage table contains a reconcile label without a reconcile control. RECONCILE and RECEIPT_READ cover the advertised reconcile command and receipt lifecycle. The unmounted controls do not add further endpoint obligations.
- **Range selectors** — Range selection updates one store field. Performance reads it as display text, while Trades and Funnel use fixture/session data without network filtering. Existing per-view local filters and generated CSVs need no endpoint.
